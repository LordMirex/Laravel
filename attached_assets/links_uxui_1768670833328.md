UX/UI & Theme System Specification 🎨

Modular Influencer Engine — Design & Theme Blueprint (v1.0)

⸻

A complete, designer-and-developer ready specification for themes, templates, UI components, interactions, accessibility, and the theme engine. Use this doc to build Figma files, Blade components, and the admin Theme Library. It’s organized so designers and devs can work in parallel and hand off assets cleanly. ✨

⸻

1 — Overview & Goals

Purpose: Define the visual system and how themes are packaged, swapped, and rendered so any creator (influencer, seller, author, musician, etc.) can pick a premium look and keep their content unchanged.

Goals
	•	Designer-first: themes must feel premium (celebrity / editorial / e-commerce quality).
	•	Modular: same content renders acceptably across all themes.
	•	Swap-safe: switching themes only affects presentation (tokens & partials), not content.
	•	Shared-host friendly: minimal runtime cost for theme switching.
	•	Accessible & performant by default.

Audience: Product owner, UI/UX designers, front-end engineers (Tailwind/Blade), backend devs implementing theme tokens, admin UX team.

⸻

2 — Design Principles (the north star) 🌟
	1.	Content-first: Layouts promote creator content (video, audio, image, copy).
	2.	Deliberate hierarchy: Big, bold hero → proof → conversion flow.
	3.	Tokenized styles: Colors, fonts, spacing, and motion as swap-able tokens.
	4.	Mobile-first: Design and interactions optimized for thumb use.
	5.	Performance-aware: Images & animations optimized; avoid heavy JS per page.
	6.	Accessible: Semantic HTML, keyboard focus, proper contrast, alt text required for key images.
	7.	Polished micro-interactions: Subtle; not flashy. Short durations, meaningful feedback.

⸻

3 — Theme System Architecture (how themes work)

Layers
	•	Content layer: canonical data (blocks, media, products). No visuals.
	•	Token layer: theme tokens (JSON) → CSS variables.
	•	Component layer: Blade/Tailwind components read tokens and render.
	•	Variant layer: template-specific partials to switch structural differences (hero variant A/B).

Workflow
	1.	Designer builds template & token set in Figma.
	2.	Tokens exported as tokens.json (colors, fonts, spacing, radii, interactions).
	3.	Dev places partials and generic components; components read tokens and render.
	4.	Admin selects theme variant → app writes site_settings.theme_config = tokenRef and the frontend loads CSS variables.

Key constraint: Theme swap should be server-side (persist tokens) and not require reformatting content.

⸻

4 — Theme Tokens (canonical list & conventions)

Tokens are JSON objects that map to CSS variables. Use clear naming, kebab-case for CSS vars.

Top-level token categories
	•	colors
	•	fonts
	•	typography (size scale)
	•	spacing
	•	layout
	•	radii
	•	shadows
	•	interactions
	•	images (hero presets)
	•	misc (e.g., container widths)

Example tokens.json

{
  "colors": {
    "primary": "#111827",
    "accent": "#ff2d55",
    "muted": "#6b7280",
    "bg": "#ffffff",
    "surface": "#f8fafc",
    "text": "#0f172a",
    "inverse-text": "#ffffff"
  },
  "fonts": {
    "heading": "Inter, system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial",
    "body": "Inter, system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', Arial"
  },
  "typography": {
    "h1": "36px",
    "h2": "28px",
    "h3": "22px",
    "body": "16px",
    "small": "14px"
  },
  "spacing": {
    "gutter": "24px",
    "space-sm": "8px",
    "space-md": "16px",
    "space-lg": "32px"
  },
  "layout": {
    "container-width": "1200px",
    "content-max-width": "900px"
  },
  "radii": { "sm": "6px", "md": "12px", "lg": "24px" },
  "interactions": { "cta-scale": 1.03, "motion-duration": "220ms" }
}

CSS variable naming
	•	--color-primary, --color-accent, --color-bg, --text-color, --muted-color
	•	--font-heading, --font-body
	•	--h1-size, --body-size
	•	--space-gutter, --space-lg
	•	--radius-md, --shadow-lg
	•	--cta-scale, --motion-duration

Best practice: keep tokens minimal and expressive. Avoid duplicating visual logic in components.

5 — Typography system ✍️

Type scale
	•	h1: --h1-size (desktop 48–60px; clamp for responsiveness)
	•	h2: --h2-size (28–36px)
	•	h3: --h3-size (22–26px)
	•	body: --body-size (16px)
	•	small: --small-size (13–14px)

Font stacks
	•	--font-heading, --font-body (store system fallback)
	•	Suggested pairings:
	•	Editorial: Playfair Display (heading) + Inter (body)
	•	Minimal: TT Norms (heading) + Inter (body)
	•	Bold/Brand: Poppins (heading) + Inter (body)

Line-height
	•	h1–h3: 1.05–1.2
	•	body: 1.5

Responsive typography
	•	Use clamp() in CSS for h1/h2 to scale between breakpoints.

6 — Color system & palettes 🎨

Token roles
	•	primary — main brand action color (CTAs)
	•	accent — secondary highlight
	•	bg — page background
	•	surface — cards, floats
	•	text — primary text color
	•	muted — secondary text, hints
	•	danger, success — status colors

Accessibility
	•	Ensure --text-color on --bg passes 4.5:1 for body text and 3:1 for large headings.

7 — Spacing, grid & responsive breakpoints 📐

Spacing scale (example)
	•	4, 8, 12, 16, 20, 24, 32, 48, 64 (CSS vars: --space-xxs, --space-xs, …)

Container
	•	max widths:
	•	--container-sm: 720px
	•	--container-md: 920px

	•	Gutter uses --space-gutter

Breakpoints
	•	Mobile: 0–639px
	•	Tablet: 640–1023px
	•	Desktop: 1024–1439px
	•	Wide: 1440px+

8 — Core components (detailed specs) 🧩

Below are components with fields, behavior, accessibility notes, and theme variances.

⸻

8.1 Navigation (header)

States: transparent hero overlay, solid (scrolled), compact mobile.

Fields
	•	Logo (image/svg)
	•	Primary nav links (label + anchor)
	•	Secondary actions (CTA button, search, socials icon)
	•	Sticky option

Behavior
	•	On mobile: hamburger opens full-screen drawer with big touch targets (44–56px).
	•	On scroll: solid background after hero threshold (configurable).
	•	Accessibility: focusable links, aria-label on hamburger, skip-to-content link.

Theme variants
	•	Classic: left logo, right nav
	•	Centered: logo centered, minimal links
	•	Store: logo left, cart/store CTA prominent

⸻

8.2 Hero / Identity block

Variants: Image hero, video hero, split hero (text + image), minimalist text hero.

Fields
	•	Title, subtitle, eyebrow, background media, CTA array, layout alignment.

Behavior
	•	If video background: autoplay muted loop, fallback poster image.
	•	CTA prominence: primary CTA uses --color-primary and scales on hover (--cta-scale).

Accessibility
	•	Provide pause control for motion-heavy heroes.
	•	Hero images must have alt text associated via media library.

⸻

8.3 Card & Content Grid

Usage: Posts, products, portfolio items.

Card elements
	•	image (ratio presets), title, meta (date/category), excerpt, badges, CTA.

Design rules
	•	Use consistent image aspect ratio (or responsive srcset) per theme.
	•	Hover state: subtle upward translate & shadow increase.
	•	Badge styles: theme token --color-accent background with --inverse-text.

⸻

8.4 Product Card (store)

Fields
	•	image, title, price, short description, badges (e.g., limited), Buy button.

Buy button
	•	primary style, opens wa.me prefilled message; provide titleattr for accessibility.

Layout variants
	•	Grid card (fashion)
	•	Minimal list (author)
	•	Carousel (featured items)

⸻

8.5 Video Grid & Player

Grid
	•	optional masonry, thumbnails, autoplay preview on hover (desktop only).

Player
	•	Lightbox with embedded YouTube/Vimeo/TikTok.
	•	Accessibility: close on ESC, focus trap in modal, transcripts (optional).

⸻

8.6 Gallery / Portfolio

Lens
	•	Masonry layout, image lightbox, full-bleed galleries.
	•	Provide next/prev keyboard arrows, swipe gesture on mobile.

⸻

8.7 Newsletter form & popups

Inline
	•	compact form (email + name) with clear consent message.

Popup
	•	Delay and exit-intent options in block settings; unobtrusive close and cookie to avoid repeat.

Validation
	•	Client-side validation + server-side duplication checks.
	•	Show success microcopy: “Thanks — check your inbox to confirm.”

⸻

8.8 Modal & Drawer
	•	Use ARIA dialog role, focus trap, return focus on close.
	•	Mobile drawers slide from bottom or side; full height for important actions.

⸻

8.9 Footer
	•	Support multiple columns: contact, quick links, socials, newsletter.
	•	Legal links and small-print (privacy, terms).
	•	Keep contrast readable.

9 — Component theming & mapping to blocks

Principle: For each block type, provide 2–4 component variants (structure) and the theme tokens change colors/typography.

Mapping example
	•	Block hero → components hero.variant-a, hero.variant-b, hero.variant-c
	•	Block store → components store.grid-card, store.list, store.promo

Implementation note: Blade components should accept a variant prop and theme_tokens read from site_settings.theme_config.

11 — Admin Theme Editor UX (what admin sees) 🧰

Theme Library page
	•	Grid of theme cards (thumbnail, category, variant chips)
	•	On hover: Preview | Apply
	•	Preview modal: shows live rendering of current content with theme tokens applied (desktop & mobile toggle)
	•	Apply flow: confirmation modal, optional “backup current theme” prompt

Theme customizer
	•	After applying a theme, allow micro-customization:
	•	Primary color picker (updates --color-primary)
	•	Font selector (dropdown match tokens)
	•	Accent color
	•	Logo and favicon upload
	•	Save writes to site_settings.theme_config (persisted).

Preview
	•	Admin sees immediate preview pane (iframe or server-rendered preview) for current content.

Undo
	•	Allow reverting to previous token set (store history 3 last themes).

12 — Asset & Figma delivery spec for designers 🎯

Per theme deliverable
	•	Figma file with pages: Desktop, Tablet, Mobile (all major breakpoints).
	•	Component library: Buttons, Cards, Hero variants, Forms, Product card, Grid systems.
	•	Token export: tokens.json (colors, fonts, sizes, radii, spacing, interaction tokens).
	•	Asset pack: hero images (1920×1080), product hero images at multiple aspect ratios, thumbnails.
	•	README with usage notes (e.g., hero minimum crop area, focal point guidelines).

Naming & export
	•	Export assets in /assets/{theme}/{image-name}-{w}w.jpg and corresponding WebP.
	•	Provide SVGs for icons and logos (prefer inline SVGs for color swap).

13 — Motion, micro-interactions & accessibility of motion 🎬

Animation tokens
	•	--motion-duration (e.g., 220ms)
	•	--motion-ease (cubic-bezier)

Micro-interactions
	•	CTA hover: scale --cta-scale with transform: translateZ(0) for GPU
	•	Card hover: translateY(-6px), increased shadow
	•	Counters: animate numbers easing in, duration 800ms

Reduce motion
	•	Detect prefers-reduced-motion: reduce and disable non-essential animations.

⸻

14 — Image behavior, focal points & cropping rules 🖼️

Focal point system
	•	Store focal coordinates (x,y 0–100).
	•	On CSS: object-position: var(--focal-x) var(--focal-y) or calculate in inline style.

Crop presets
	•	Hero: 16:9 or 3:2
	•	Square: 1:1 (profile, thumbnails)
	•	Portrait: 4:5 (cards)

Mobile adjustments
	•	Admin can specify mobile-crop-mode for hero: top|center|focal.

⸻

15 — Accessibility & semantic requirements ✅
	•	Headings must be used in sequence (H1 per page).
	•	Images: alt text required for hero/featured; optional for decorative (role=presentation).
	•	Color contrast: ensure 4.5:1 for body, 3:1 for large text.
	•	Keyboard nav: all controls focusable, skip links, focus ring visible.
	•	Forms: accessible labels, ARIA-described by success/error messages.
	•	Modals: trap focus; restore focus on close.

⸻

16 — Performance & optimization rules ⚡
	•	Use srcset and sizes for all images.
	•	Generate responsive images at upload; serve WebP/AVIF if available.
	•	Inline critical CSS for hero above the fold.
	•	Lazy-load below-the-fold images.
	•	Minimize main JS; prefer CSS-based interactions where possible.
	•	Defer non-critical third-party scripts (analytics).

⸻

17 — Theme implementation guidance for devs (how to code it)

1. Token injection
	•	At page render, fetch site_settings.theme_config.tokens
	•	Render a <style id="theme-tokens">:root { --color-primary: #...; ... }</style> block into head.

2. Component API
	•	Components accept variant and content props.
	•	Components read CSS variables for colors and tokens; use Tailwind with custom properties or dynamic CSS classes.

3. Variant partials
	•	components/hero/variant-a.blade.php, variant-b.blade.php etc.
	•	Keep markup semantic; only swap structure when necessary.

4. Admin save
	•	When admin applies variant -> store theme_ref and custom_overrides (colors/fonts).
	•	Provide rollback.

5. Fallback
	•	If tokens missing, use default_theme_tokens.json packaged with app.

18 — Testing & QA checklist for themes

Visual
	•	Each theme renders same content across desktop/mobile/tablet.
	•	No overflow/overlap on small displays.
	•	Hero focal point respected at breakpoints.

Accessibility
	•	Contrast checks using automated tool (axe/Lighthouse).
	•	Keyboard nav test: tab through nav, modals, forms.

Performance
	•	Lighthouse audit baseline: PWA not required, but aim for Performance > 50 on shared hosting simulated.

Theme switch
	•	Apply theme → preview → confirm → verify content persists and layout updates.
